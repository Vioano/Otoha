# Otoha 源码移植记录

日期：2026-10-24。用户明确要求将本机相关项目移植到 Otoha，并统一命名。

## 已迁入的通用实现

- `packages/graph`：图谱、渲染器、查询、看板、团队签名变更、历史恢复与维护中的测试。
- `services/collaboration`：Python 服务、身份与权限、持久消息、读取投影、回执、MCP、接入与会话桥接；保留一个旧版本数据库升级测试夹具。
- `apps/cli`：Go 原生客户端、项目接入、连接与 Git 代理、后台接收器、宿主适配与测试。
- `integrations/mailbox`：GitHub 收信工具、Skill、安装工具与测试。

新增 `bin/otoha.mjs` 作为源码入口，支持 graph、server、message、mcp、client、mailbox。原生构建产物在 `dist/`，不提交二进制包。

## 改名与隔离

产品文案、代码标识符、文件路径、Go 模块与包名、CLI 参数、环境变量、默认目录、邀请前缀、服务标签及图谱签名域已切换到 Otoha。来源记录、原版权署名与不相关的第三方品牌保留真实名称。

这是独立源码分支的迁入，不是生产状态迁移。既有服务、凭据、邀请、数据库和 receiver 不被新构建接管。新旧协议前缀、签名域和默认目录的差异是明确边界；真实部署迁移需匹配两端并核对现存状态。

公开发布地址已指向 Otoha 仓库。当前没有正式二进制发行版，默认 Windows 下载入口明确停止并提示源码构建，避免误取旧产品发布包。

## 来源与未迁入内容

固定提交和逐文件哈希见 [import-manifest.json](provenance/import-manifest.json)，适用许可与原作者见 [NOTICE.md](../NOTICE.md)。导入前检查了本机状态；协作服务原目录有未提交运维与存储工作，本轮没有把它们混入通用协作实现。

原项目的真实服务器配置、账号资料、接入包、运行数据库、团队消息、运维日志、截图和机器专用桌面/网络工具留在原处。当前项目没有安装真实后台服务，也没有发送团队消息。

## 仍需继续开发

迁入代码提供基础能力，不等于五项哲学已经完整落地。分级通知、持续对齐 Agent、需求实例反馈与工程图谱的关联、自适应调度仍需继续实现。真实跨机器、多成员与各 Agent 宿主的实际阅读和空闲唤醒需要分别验收。
