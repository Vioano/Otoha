# Otoha 需求状态与演化证据

更新：2026-11-06，Asia/Taipei。本文先固定本轮可核对的需求依据，供审阅和后续实例使用；不表示真实实现或用户验收完成。

当前判断：Otoha 是安静、可靠、低资源的常驻协作基础设施。仓库、消息、图谱和工作页由同一个 Otoha 项目管理；软件承担接入与协议复杂性。开发应先用明确标注为模拟的可操作网站跑通具体需求与流程，吸收反馈后再做真实实现。当前没有开发独立 Coding Agent 的计划。

## 1. 怎样判定一条想法

需求状态与取证状态分别记录。用户决定可以仍然有效，而本轮尚未取得其最初原话。

| 需求状态 | 判定依据 |
| --- | --- |
| 用户明确、仍有效 | 真实用户消息或本轮明确约定；未发现后续替代 |
| 已否定或被替代 | 后续用户消息改变同一条件；指出旧、新消息的关系 |
| 用户构想、尚未成熟 | 用户提出可能性、问题或方向，具体机制尚未决定 |
| 助手单方建议 | 助手的分析、架构、字段或排期，未找到用户采纳证据 |

另有取证标记“旧记录为已定，本轮原话待补证”。它不是第五种产品立场，尤其不等于用户未决定、已经否定或只由助手提出。不用聊天最后更新时间排序观点；只比较相应消息及其具体条件。请求总结、继续研究或保存笔记，也不自动等于逐项重新批准助手的全部表述。
