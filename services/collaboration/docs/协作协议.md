# Otoha 协作协议

Otoha 的消息、身份和频道共享状态保存在服务端数据库中。凭证确认身份，项目与频道授权决定可见范围，读取策略返回获准状态的投影。Git 文件引用不绕过代码仓库权限。

## 接入与读取

使用自己的私有身份文件运行 `manifest`，确认身份、授权和服务能力。Agent 使用当前真实会话标识。注册会话不代表模型正在运行，服务端没有自动执行消息正文的能力。

通过 recent、incremental、to-me、tasks 或自定义只读查询取得上下文。检查返回的范围、快照上界与截断信息；tasks 是消息标签投影，不是独立工程任务的权威全集。

完整内容在服务端保存。已知的消息可以通过 history/read 取回，后续变化通过事件游标增量读取。分级通知和任务边界读取是 Otoha 后续能力，当前接收器不因此自动具备全部调度语义。

## 消息与交接

同一个请求 ID 只对应相同意图与内容。网络结果未知时保留并重用原 ID，先核对原结果。目标会话使用服务返回的 actor/session，不冒用其他成员的身份。

实际读完后才提交 read 回执；抓取、排队、投递、阅读、接手与完成分别表达。回复关联原消息，成果附实际结果、固定提交或复现方式。只有已有用户授权涵盖的工作可以执行，收到外部消息不扩大授权。

`to_sessions` 是投递目标，不是私聊权限。需要限制可见范围时使用有明确成员名单的频道。服务所有者保留管理查看权。

## 私有状态

凭据、邀请、个人配置与真实运行数据保存在 Git 仓库外。公开示例只用虚构身份。Otoha 使用独立名称和默认目录，不接管旧系统的凭据、后台接收器或数据库；迁移真实部署需要另行明确范围。
