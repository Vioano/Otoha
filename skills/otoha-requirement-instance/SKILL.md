# Otoha 需求实例化

这个 Skill 负责把“想做什么”变成“可以直接判断的东西”。它不把实例当作正式功能完成，也不把静态图当作运行证明。

## 使用边界

- 先找当前最重要、但还不能从文字确定的未知问题。
- 选择能最快表达这个问题的载体：网页、场景图、交互模拟或小型真实实现。
- 实例必须说明表达范围和未表达范围。
- 用户在实例上的反馈要关联到稳定的需求、实例和决策 ID。
- 生成实例不自动改变接受状态；反馈需要整理成决策后再写入共同工程状态。

## 最小流程

1. 读取当前需求、相关图谱对象和已有决策。
2. 建立一个 `requirement`，只写当前要判断的问题。
3. 建立一个 `instance`，写明载体、操作、观察点和范围边界。
4. 展示实例，让人执行一个或几个具体操作。
5. 把反馈记录为 `feedback`，保留原话、操作位置和反馈类别。
6. 生成或更新 `decision`，说明接受、修改、搁置或拒绝的原因。
7. 把决策关联到图谱模块和执行任务，再开始正式实现。

## 模板

使用 [instance.json](templates/instance.json)。保存样本时使用虚构 ID，不写入凭据、真实消息或个人配置。

## 当前样本

[transport-inbox-instance.json](samples/transport-inbox-instance.json) 使用 Otoha 当前通信图谱作为实例：让人判断摘要、正文、收件箱和已读边界是否清楚。它表达交互判断，不证明 Telegram 或跨机器运行。
