# 可执行检查

复用项目已有制作和审查链路。两项检查都使用 Python 3 标准库，无需安装 Otoha 服务或额外依赖。下文 `<skill>` 是本 Skill 目录，不是项目工作目录。

## 实际图片几何

```sh
python3 <skill>/scripts/check_pptx_images.py work/build/deck.pptx --json
```

检查 PPTX 内的实际图片、源像素尺寸、裁切窗口与放置图框。输出包内真实页序、shape ID、图像 part、裁后尺寸、图框、横纵倍率与诊断。不相信代码中的 `contain` 或锁定比例声明。

- `0`：已支持范围内没有比例失真；没有适用图片也不代表作品通过。
- `1`：实际比例失真，阻断该候选。
- `2`：输入或实现超出已支持范围，保持未验证。

当前覆盖 PNG/JPEG 的嵌入页内图片及标准裁切/图框。组变换、tile、非零目标 fillRect、继承图片、图形填图和未知格式不静默放行。默认相对比例误差容忍为 0.1%，用于裁切与坐标量化；这不是审美阈值。人物保护区、动作解释力、相邻页风格和原生显示仍须实际审查。

确有已确定的可拉伸对象时，以 `--policy policy.json` 精确限定，例外不是全页豁免：

```json
{"allowed_stretch":[{"slide":1,"shape_id":"2","reason":"本对象是明确采用的可拉伸底纹"}]}
```

例外理由应能回到实际采用决定，不能为消除报错事后批准人物拉伸。单页候选的包内页序可能是 `1`，与整套作品中的逻辑页码分开记录。

## 已提交的独立审查结果

```sh
python3 <skill>/scripts/check_review_result.py \
  --report work/review/report.json \
  --manifest work/review/input-manifest.json \
  --artifact work/build/deck.pptx --json
```

输入清单在审查前冻结当前文件及 SHA-256；报告记录实际逐页判定和推导过程判定。用当前文件运行结果检查，不把审查程序的 `returncode=0` 当质量结论。

脚本读取既有格式：`overall_verdict`、`viewed_pages`（`page/image_path/page_verdict/findings`）、`process_review.verdict`，以及可选的整体/过程 findings。清单为 `inputs[{path,sha256}]`；同一清单有参考图片时，可用 `review_pages` 明确选择作品页，所选页仍须在 inputs 中。相对路径按声明文件所在目录解析。

- `0`：所提交的整体、逐页与过程判定通过，必需观察齐备，覆盖及当前文件匹配。
- `1`：存在明确不通过、需返修或未解决的 blocker/major，阻断交付。
- `2`：结论/严重性未知、缺页、必需观察缺失、文件改变或产物未被绑定，保持未验证。

`required_unverified` 非空表示本次必需但仍缺的观察，返回未验证。`not_verified` 仅保留原报告范围，脚本不从自然语言猜它是否必需；项目须按已确定的需求在审查前明确必需范围，不能靠删掉清单项宣布完成。指定 `--artifact` 后，目标原生文件必须被清单绑定，否则旧页图不能给新 PPTX 放行。

这项检查不认证审阅者身份或独立性，不证明其真的读图，也不替它判断观察是否正确。没有报告到清单的摘要绑定时，输出明确标明采用页路径与当前输入哈希匹配；不能补写历史签名或把当前一致写成已验证整个审查过程。

## 接回原工作流程

把两项命令接到已有构建或交付验证中。任一非零都停止“已完成”交付：具体几何问题修在放置层，具体视觉问题交原作者/制作侧返修，随后查看实际新版本。几何通过、审查工具执行完成、审美通过、原生实播与用户接受分别记录。

先用[可操作正反例](../assets/review-cases.html)核对判断：拉伸方式在源窗与目标比例相同时也可能合规；取消遮挡白条不代表骑缝已修；“先选一项”是必要约束，不能当作辅助废话删掉。全套审查仍看全部当前页面，不能用其中一个好页面代表整个作品。
