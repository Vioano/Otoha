# 内容制作与双重审查

**推导过程和最终成品都要审查。** 页面各自整齐，不等于整套作品成立；有一份设计说明，也不等于真实画面支持它。此 Skill 正在真实项目中试用，不把流程存在称为效果已验证。

## 先接住作品

先读当前任务、已有风格与采用稿、用户最近反馈及项目的制作规范。明确受众、使用情境、输出格式、时长与必要内容。用户要求复用某项目管线时，读其原规范和实际审查记录，提取完整义务；不能只借配色、导出与“有独立审阅者”。项目特定字号、页型、作者模型和时长不自动成为通用规则。

明确指定完整复用的项目，以其原规范和已跑通管线为主，只对题材差异作必要适配并说明；不要临时另造一套平行审美框架。通用 Skill 负责保留和执行这些义务，不替原项目重定美术标准。

沿用现有目录、作者会话和审查记录。小修直接在原链路处理；整套重编才重做受影响的导演与设计依据。复用随附检查和项目已有构建入口，不另建消息服务、状态库或自填评分系统。Otoha 用于已有授权下的协作与引用，不是使用此 Skill 的安装前提。

## 在制作中形成依据

先形成分层推导，再制作局部。按作品实际形式保留以下关系：

1. **整场目标与观看弧线**：观众最后要理解、感受或能做什么；全程怎样推进到那里。
2. **段落顺序与表达**：每段讲什么、怎样呈现、为何在此处，以及与前后怎样衔接。
3. **每页任务**：它承担哪一项认知、叙事或操作任务，怎样推进所属段落。
4. **元素设计**：文字、图像、关系、位置与尺度怎样完成该页任务。
5. **有动画时的时间表达**：观众要观察什么、以何顺序出现、何处停驻、为何转场；没有动画不强加动画。

每层选择从上一层推导，并始终受整场目标约束。局部漂亮不能补偿整体节奏失败；改动局部时回看它是否仍服务于上层。画出能连续观看的粗分镜；发现长段都在读文字，应判断观看任务是否单一，再选择场景、图解、对话、演示或留白。不要用“每页必须有图”或固定图文比例代替导演判断。

布局承载信息的表达意义。步骤、比较、因果和状态差异用空间、连接、对齐及时间呈现，不把所有关系压成扁平概括。必要正文仍保留，删字本身不证明信息已经被表达。样图或真实布局让人看不懂时，退回重新设计，不能加解释段落或事后理由补成通过。

每个可见元素都有作用与放置依据，包括文字、图片、关系线、留白安排和运动。用**明确继承＋特例推导**保持轻量：

- 通用元素引用已论证的字体角色、网格、关系对齐、阅读尺度等，并说明它为何属于该角色；可按同一约束覆盖一个明确的元素组，不逐字重复长文。
- 新关系、冲突或关键画面先保存任务与约束、构图草稿和实际候选，再记录选择。候选须改变阅读路径或关系表达，换颜色不算。
- 特例说明为什么出现、在何处、用何尺度、怎样帮助理解，并以真实渲染或播放验证。尺寸算式能保证一致性，不能证明某坐标是唯一审美最优。
- 动画写明当前焦点、要观察的变化、关键状态、停驻与转场理由；以实际播放检验顺序和节奏，不只抽帧。

保留真实发生的版本和返修。依据缺失就标缺失，从当前版本重新设计；不能事后编理由追认旧成品。具体判断例见 [审查依据](references/review-basis.md)。

## 审查打样入口与结果

生图提示词也是设计依据的一部分。生成前，核对本次适用的用户约束、整体与当前层级的目标、必要内容、候选之间要比较的差异；检查提示词是否已经引入被禁止的冗余说明、无意义装饰或错误关系。不机械复制全量 AGENTS.md，不把负面词清单当作已理解约束。

多打样应比较实质不同的构图、阅读路径或时间表达，而非换色凑数。出图后再对照同一目标和约束，检查整体节奏、图文关系及必要信息，记录采用、修改和舍弃的部分。样图可能犯错；不合格部分退回修改或重做，不因“按参考还原”获得豁免。生成稿中的文字、箭头、坐标和运动意图都不是正确性的证据；落实后仍需审真实成品。严格项目由既定独立 verifier 同时核对这些前置选择，不新增一套常驻审批系统。

打样贯穿制作，不是只在开头做一次。中途遇到构图、美感或表达卡点，可把当前真实画面作为新一轮输入，连同所属层级的目标和具体问题探索替代安排；审查新样图、落实到实际作品，再连续回看受影响的整体。局部问题可以局部打样，不必重开全套设计。

每轮提示词随制作推进动态调整：输入当前版本、本轮要解决的问题、上层目标、最新反馈和仍适用的约束；更新已经改变的要求，舍弃失效假设，保留与取舍有关的版本。第一轮的探索目标不必延续到后续轮次。新样图提出的是候选，不自动改写已确定的需求或授权。方向清楚的小修直接完成，不以固定轮数或图片数量替代判断。

## 用一个 HTML 入口方便人判断

用户需要统一工作稿时，复用现有 HTML 入口，把**顺序观看、单页实际画面、相关讲稿、设计依据、候选取舍和问题**对应起来。默认先看到作品；依据按页或元素就地展开，保留阅读位置，不把主视图做成制作日志。

HTML 是审阅载体。PPTX、PDF、DOCX 或视频仍按实际交付格式渲染、打开或播放；不能用 HTML 模拟画面、拼图或封面代替整套原生结果。没有依据或尚未审查的地方清楚显示未完成。不要把私人来源、凭据或本地运行状态随可共享页面发布。

## 保持分工

按任务已有约定确定内容作者、制作整合者与独立 verifier。指定作者负责的可见文案及教学取舍，发生问题后回到原作者会话修订；制作侧不暗中补写。模型只是本任务配置，不是审查可信性的来源。

至少一位未参与本轮制作的独立 verifier，取得原始要求、采用方向、必要来源、当前依据和实际成品。独立首审使用新上下文；不把作者自评或旧“通过”当答案。记录真实审阅者与覆盖范围。技术审阅、内容审阅和美术审阅分别报告，不能相互代签。

## Verifier 审两条链

1. **整体与成品。** 按真实顺序看完全部作品，再看关键细部。判断全套起承、密度、观看任务、留白与重复是否服务于理解；检查实际字形、对齐、图文关系、必要信息、内容与来源。动态内容要实际播放，原生交互要实际操作。
2. **推导与实现。** 先核对整场到段落、页面、元素及适用动画的分层推导，再对照任务、约束、草稿、候选与元素关联，检查各层是否回应上层、继承是否适用、特例是否有依据、采用选择是否回应任务，以及实际结果是否支持原先预计。全体元素须有明确覆盖；优先细查关键页、例外和新组合。账本齐全但关系仍不清楚，仍要重构。

记录具体观察，再给范围明确的结论。区分可确定的结构检查、实际渲染/播放观察和审美判断；未看、无法测或缺依据就是未验证，不是“不适用”或“满足”。总分、文件存在、无溢出、CLI 完成均不能抵消具体阻断。

## 运行检查，并把失败接回制作

PPTX 图片先用 [check_pptx_images.py](scripts/check_pptx_images.py) 核实际裁窗与图框；独立审查完成后用 [check_review_result.py](scripts/check_review_result.py) 核审查结论、逐页覆盖和当前输入版本。具体命令、报告范围与退出码见[可执行检查](references/checks.md)。将它们接入当前项目已有构建/交付检查入口，非零就保持阻断或未验证，回原制作链路修改；不要只保存报告后继续交付。

检查结果不会生成审美判断。独立 verifier 必须实际看图、连续观看和按需操作，再提交具体发现；审查程序运行成功不等于审美通过。未知的报告结论、缺页或版本不一致不能被当作通过。几何通过但画面关系、动作或整套节奏仍不成立，照样退回重做。

可运行的[正反例](assets/review-cases.html)用于比较裁切比例、图文边界和并列选择，使用虚构向量素材。检查正例在改变参数后是否仍满足条件，不能因为被标为“正例”就放过错误；它们不证明真实作品已过审。

## 返修与交付

问题写清页/元素/片段、实际现象、对理解的影响及依据，交制作侧沿根因修改。Verifier 不同时改同一成品。制作后复看问题、受影响的相邻关系，并连续复看当前整体；新方向或新内容补对应覆盖，不机械重开所有角色。

结论绑定实际最终文件/构建及必要哈希。之后有变化，就复验受影响部分；未变部分可说明依据后复用证据。原生实播、真人彩排、独立审阅、用户接受与正式发布分别记录。未解决的阻断继续返修，真实资源边界内仍未完成的部分如实交代，不用旧版通过覆盖新版。

交付入口、原生文件、谁审了什么、已修问题与剩余未验证项。用户反馈应回到共同需求和后续制作；能可靠自动检查的具体失误，再接入项目已有 lint 或测试，主观节奏与审美继续由真实作品判断。
